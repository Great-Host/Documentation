# 🔌 Reseller API: Getting started

## Overview
The **Reseller API** lets you build your own website, app or Discord bot on top of GreatHost. With it you can register customers, sell services and give your customers full control of them, all from your own software and under your own brand.

- Base URL: `https://greathost.es/api/reseller/v1`
- Format: JSON in, JSON out.
- Available products: **Minecraft Paper** game servers and **VPS KVM** (every location). VPS can also be sold in your storefront, without the API.

The API uses the same store, prices, customers and invoices as your storefront: a customer created through the API appears in your **Customers** tab, and so on.

## Requirements
- An **active** reseller store.
- The products you want to sell **listed with a price** in **Products & pricing**. The API only sells what is on sale in your store.
- Your store in the default billing mode (customers pay you directly).
- Enough GreatHost **credit**: every order and renewal through the API is charged to it.

## How you charge your customers
When you sell through the API, **you charge your customer yourself**, in your own app, with whatever payment method you like. When you then place the order through the API, GreatHost charges the wholesale price to your credit and creates the service. The same goes for renewals.

## API keys
Create keys in **Reseller Panel → API**:

1. Give the key a **Name** (only for you, for example "My website").
2. *(Recommended)* Enter your server's IP address under **Allowed IPs**. The key will then only work from those IPs.
3. Click **Create key**.

The key looks like `ghr_live_…` and is **shown only once**. Copy it and store it safely (for example in an environment variable on your server). If you lose it, revoke it and create a new one. You can have up to 5 active keys.

> **Warning:** The key gives full access to your store. **Never** put it in browser JavaScript, a mobile app or a public repository. The API refuses requests made from a web browser. Always call it from your own server.

## Authentication
Every request needs your API key:

```http
Authorization: Bearer ghr_live_xxxxxxxxxxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Requests that act **on behalf of one customer** (their orders and services) also need that customer's token:

```http
X-Customer-Token: <customerToken>
```

You get the `customerToken` when you register or sign in a customer (see **API - Customers and orders**). Tokens expire after a few days: when you receive `INVALID_CUSTOMER_TOKEN`, sign the customer in again.

Other rules:
- Always use **HTTPS**.
- Send credentials only in headers, never in the URL.
- Send `Content-Type: application/json` with every request that has a body.

## Responses
Every response has a `success` field.

Success:
```json
{ "success": true, "service": { "...": "..." } }
```

Error:
```json
{ "success": false, "code": "PRODUCT_NOT_FOUND", "message": "This product is not available through the API" }
```

Use `code` in your program (it does not change) and show `message` to people (it may change).

### Common error codes
| HTTP | Code | Meaning |
|---|---|---|
| 400 | `INVALID_REQUEST`, `INVALID_JSON` | Something in the request is missing or wrong. |
| 401 | `INVALID_API_KEY` | Missing, wrong or revoked key. |
| 401 | `CUSTOMER_TOKEN_REQUIRED`, `INVALID_CUSTOMER_TOKEN` | Missing or expired customer token. |
| 402 | `INSUFFICIENT_CREDIT` | Your GreatHost credit is too low. Top up and retry. |
| 403 | `IP_NOT_ALLOWED` | The key is used from an IP that is not in its allowed list. |
| 403 | `BROWSER_NOT_ALLOWED` | The request came from a web browser. |
| 403 | `PANEL_PENDING`, `PANEL_SUSPENDED` | Your store is not active. |
| 403 | `CUSTOMER_SUSPENDED` | You suspended this customer. |
| 403 | `SERVICE_NOT_ACTIVE` | The service is suspended or ended. |
| 404 | `SERVICE_NOT_FOUND`, `PRODUCT_NOT_FOUND`, `NOT_FOUND` | It does not exist or does not belong to this customer. |
| 409 | `OUT_OF_STOCK` | The product is temporarily out of stock. |
| 409 | `CONFLICT`, `BUSY` | The service is busy with another operation. Wait and retry. |
| 429 | `RATE_LIMITED` | Too many requests. Wait the number of seconds in the `Retry-After` header. |
| 500 / 502 | `INTERNAL_ERROR`, `UPSTREAM_ERROR` | Something failed on our side. Retry later or contact support. |

## Rate limits
- **300 requests per minute** per key, across all endpoints.
- Some actions have their own, lower limits (for example 10 power actions per minute per service, 30 orders per hour per key).
- Every response includes `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset`.
- After 20 requests with a wrong key in 15 minutes, the IP is blocked for 15 minutes.

## Idempotency (avoid double orders)
Every `POST /orders` request needs an **`Idempotency-Key`** header: a unique value you generate for each order (8-100 characters, for example a UUID).

If the network fails and you are not sure whether the order went through, **send exactly the same request again with the same key**: you get the original answer back instead of a second service. Use a **new** key for every new order.

## Money format
All amounts are in **cents**, as whole numbers: `250` means 2.50 in your store's currency. `priceLabel` gives a ready-to-show text like `"2.50"`.

## Check that everything works
```bash
curl https://greathost.es/api/reseller/v1/account \
  -H "Authorization: Bearer $GH_KEY"
```

You get your store, your key and the list of products the API can sell.
