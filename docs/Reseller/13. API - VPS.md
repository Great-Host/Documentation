# 🖥️ Reseller API: VPS (KVM)

## Overview
You can sell our **VPS KVM** plans under your own brand and give your customers full control of them: power, console, reinstall, backups, snapshots, extra IPs, plan changes and more.

VPS are sold **only through the API**. They never appear in your storefront, and your customers manage them from your own app.

Before you start, list the VPS plans you want to sell in **Products & pricing** (they have the **API only** badge). Each location is a separate product line:

| `game` | Location |
|---|---|
| `vps-v2` | Spain (Madrid) |
| `vps-v2-us` | United States |

All endpoints below need `Authorization` and `X-Customer-Token`. Base URL: `https://greathost.es/api/reseller/v1`.

## 1. Build your order form: `GET /vps/catalog`
No customer token needed. Returns, for every location where you sell VPS:

```json
{
  "success": true,
  "regions": [
    {
      "id": "es",
      "game": "vps-v2",
      "label": "Spain",
      "location": { "name": "España", "flag": "es", "city": "Madrid, España" },
      "available": true,
      "maintenance": false,
      "cycleDays": 30,
      "deleteAfterDays": 5,
      "operatingSystems": [
        { "id": "debian-12", "name": "Debian 12 (Bookworm)", "family": "debian", "eol": false, "minDiskGb": 10 },
        { "id": "ubuntu-24.04", "name": "Ubuntu 24.04 LTS", "family": "ubuntu", "eol": false, "minDiskGb": 10 }
      ],
      "features": {
        "reinstall": true, "rescue": true, "backups": true, "snapshots": true,
        "hostname": true, "upgrade": true, "downgrade": false,
        "extraIps": true, "maxExtraIps": 5, "extraIpCostCents": 300
      },
      "plans": [
        {
          "productId": "8c1f…", "plan": "kvm-1", "name": "KVM 1",
          "priceCents": 650, "currency": "EUR",
          "resources": { "cores": 2, "memory": 8192, "disk": 40960, "trafficTb": 5, "uplinkMbps": 125, "storageType": "NVMe", "backups": 2, "snapshots": 2 },
          "inStock": true
        }
      ]
    }
  ]
}
```

- `cycleDays`: length of one billing cycle, in days.
- `deleteAfterDays`: how many days an unrenewed VPS is kept (stopped) before it is deleted.
- `eol: true`: the operating system no longer receives updates from its vendor. You may want to hide it.
- Some systems need more disk or memory than small plans offer (`minDiskGb`, `minMemoryMb`).
- `extraIpCostCents`: what an extra IPv4 costs you per cycle.

## 2. Order a VPS: `POST /orders`
Needs `X-Customer-Token` and `Idempotency-Key`.

```json
{
  "productId": "8c1f…",
  "serviceName": "Jane's VPS",
  "autoRenew": true,
  "vps": {
    "osId": "debian-12",
    "hostname": "web01",
    "password": "MyRootPass2026",
    "sshKeys": ["ssh-ed25519 AAAAC3Nza… jane@laptop"],
    "uefi": false
  }
}
```

| Field | Required | Notes |
|---|---|---|
| `productId` | yes | A VPS product from `/vps/catalog` or `/products`. |
| `serviceName` | no | Shown in your panel. |
| `autoRenew` | no | `true` by default. See **Billing**. |
| `vps.osId` | yes | An `id` from `operatingSystems`. |
| `vps.hostname` | no | 1-63 characters: letters, numbers and inner hyphens. |
| `vps.password` | no | Root password: 10-72 characters, with at least one lowercase letter, one uppercase letter and one number, no spaces. If omitted, a secure one is generated. |
| `vps.sshKeys` | no | Up to 5 OpenSSH public keys, added to `root`. |
| `vps.uefi` | no | Boot with UEFI firmware. |

> **Note:** The password is never returned in the order response. You (or your customer) can read it at any time from `/vps/credentials`, including the generated one when you do not send a password.

Answer (`201`): the service, with a `vps` block. The VPS keeps being built in the background for a few minutes:

```json
{
  "success": true,
  "service": {
    "id": "a41e…",
    "type": "vps",
    "region": "es",
    "status": "active",
    "nextDueAt": "2026-11-24T10:00:00.000Z",
    "billing": { "autoRenew": true, "cycleDays": 30, "priceCents": 650, "nextRenewal": { "amountCents": 650, "costCents": 380, "marginCents": 270, "extraIps": 0 } },
    "vps": { "id": "…", "status": "provisioning", "progress": { "step": "queued", "percent": 5 }, "network": { "ip": "203.0.113.25" } }
  }
}
```

Specific errors: `INVALID_OS`, `INVALID_HOSTNAME`, `INVALID_SSH_KEY`, `OUT_OF_STOCK` (409), `VPS_MAINTENANCE` / `VPS_UNAVAILABLE` (503), plus the common order errors.

## 3. Wait until it is ready: `GET /services/:id/vps/progress`
```json
{ "success": true, "status": "provisioning", "progress": { "step": "create", "message": "Creating the virtual machine", "percent": 40 }, "error": null }
```

Poll every 5-10 seconds until `status` is `active`. It normally takes 2-5 minutes.

After that, `vps.guestSetup` (in `GET /services/:id/vps`) tells you when password login over SSH is ready (`state: "done"`). Until then the VPS is up but may only accept SSH keys. If it ends in `failed`, call `POST /services/:id/vps/repair-access`.

If the deployment fails, your credit is refunded automatically, the service goes to `failed` and it is retried from scratch.

## 4. Give your customer access

### `GET /services/:id/vps/credentials`
```json
{
  "success": true,
  "credentials": { "username": "root", "password": "MyRootPass2026", "host": "203.0.113.25", "port": 22, "protocol": "SSH" }
}
```

Every read is recorded in your activity log. Limited to 20 per minute.

### `GET /services/:id/vps/console`
Opens a browser console session (noVNC) for that VPS only, valid for a limited time:
```json
{ "success": true, "console": { "url": "https://…", "expiresAt": "…", "expiresInMinutes": 60 } }
```
Open `url` in a new browser tab. Request a new session when it expires.

> **Note:** The console page is served from our infrastructure address, not from your domain.

## Reading the VPS
| Method | Path | What you get |
|---|---|---|
| GET | `/services/:id/vps` | Everything: status, power, IPs, plan, OS, location, features, plus `billing`. |
| GET | `/services/:id/vps/status` | Live status: `running` / `stopped`, uptime, CPU, memory, disk usage. |
| GET | `/services/:id/vps/stats?seconds=3600` | Usage history (up to 14 days). |
| GET | `/services/:id/vps/traffic?days=30` | Daily traffic, this month's total and the plan's allowance. |
| GET | `/services/:id/vps/logs?limit=50` | History of actions on the VPS. |

Important fields of `GET /services/:id/vps`:
- `status`: `provisioning`, `active`, `reinstalling`, `restoring`, `suspended`, `expired`, `error`.
- `power`: `running` or `stopped`.
- `network.ip`: the public IP. `network.privateIp`, `gateway`, `netmask` and `nameservers`: the network settings inside the VPS (needed to configure extra IPs).
- `capabilities`: which features are available. Hide the buttons that are `false`.

## Power and settings
| Method | Path | Body | Notes |
|---|---|---|---|
| POST | `/vps/power` | `{ "action": "start" }` | `start`, `stop` (hard), `shutdown` (clean), `restart`, `reset`. 10 per minute. |
| POST | `/vps/hostname` | `{ "hostname": "web02" }` | |
| POST | `/vps/rescue` | `{ "enable": true }` | Boot into a rescue system. `false` to leave it. |
| POST | `/vps/firmware` | `{ "uefi": true, "tpm": false }` | |
| POST | `/vps/balloon` | `{ "enabled": true }` | Memory ballooning. |
| POST | `/vps/boot-order` | `{ "order": "scsi0;ide2" }` | Disk first or CD first. |

All paths are under `/services/:id`.

## Reinstall
`POST /services/:id/vps/reinstall`

```json
{ "osId": "ubuntu-24.04", "password": "NewRootPass2026", "hostname": "web01", "sshKeys": ["ssh-ed25519 AAAA…"] }
```

> **Warning:** Reinstalling **erases the whole disk**. Ask your customer to confirm first.

The answer comes immediately; follow `/vps/progress` until it is `active` again. If you omit `password`, a new one is generated (read it from `/vps/credentials`). Limited to 20 heavy operations per hour per VPS.

## Backups
| Method | Path | Body |
|---|---|---|
| GET | `/vps/backups` | Lists backups, the limit (`max`) and the automatic schedule. |
| POST | `/vps/backups` | `{ "rotate": false }` |
| POST | `/vps/backups/delete` | `{ "volid": "…" }` (the `volid` from the list) |
| POST | `/vps/backups/restore` | `{ "volid": "…" }` |

- Each VPS can keep a limited number of backups (`max`). When it is full, `POST /vps/backups` answers `backup_limit_reached` (409) with the oldest backup. Send `{ "rotate": true }` to replace the oldest one automatically.
- **Restoring replaces the current disk** with the backup.

### Automatic backups
| Method | Path |
|---|---|
| GET | `/vps/backups/schedule` |
| PUT | `/vps/backups/schedule` |
| DELETE | `/vps/backups/schedule` |

```json
{ "enabled": true, "frequency": "daily", "hour": 3, "minute": 0, "retention": 2, "onLimit": "rotate" }
```

| Field | Values |
|---|---|
| `frequency` | `daily`, `weekly` (+ `weekday` 0-6, 0 = Sunday), `custom` (+ `weekdays`: array of 0-6), `monthly` (+ `dayOfMonth` 1-28) |
| `hour` / `minute` | Local time of the VPS location. `minute` is `0` or `30`. |
| `retention` | How many automatic backups to keep (up to the VPS limit). |
| `onLimit` | `rotate` (delete the oldest) or `skip` (do not back up when full). |

## Extra IPv4 addresses
| Method | Path | Body |
|---|---|---|
| GET | `/vps/ips` | The extra IPs, limits, stock and prices. |
| POST | `/vps/ips` | `{ "priceCents": 400 }` *(optional)* |
| POST | `/vps/ips/:poolId/cancel` | Remove it at the end of the paid period. |
| POST | `/vps/ips/:poolId/keep` | Undo a scheduled removal. |

When you buy an IP:
- Your credit pays **the rest of the current cycle** now. From the next renewal, it is part of the renewal price.
- `priceCents` is what **you** bill your customer per IP and per cycle. It cannot be lower than your cost and applies to every extra IP of that VPS. If you omit it, your cost is used.
- The answer gives the public `ip` and the `privateIp` to configure inside the VPS. **Restart the VPS** so it picks up the new address.

## Changing the plan
| Method | Path | Body |
|---|---|---|
| GET | `/vps/plans` | Your VPS products in the same location, with `allowed: true/false`. |
| POST | `/vps/plan` | `{ "productId": "…" }` |

- Only plans of the **same location** can be chosen, and the disk can never shrink. Downgrades may be disabled (`features.downgrade`).
- Your credit pays the difference for **the rest of the current cycle**. From the next renewal the new price applies.
- The answer includes an invoice with the amount you should bill your customer for the rest of the cycle.
- Reboot the VPS to see the new disk size.

## Billing
### Renewals
- A VPS renews every `cycleDays` (normally 30 days). The date is in `nextDueAt`.
- **Your credit is charged only when the VPS actually renews.** We never charge you for a cycle you did not renew.
- The renewal price is the plan price plus any extra IPs.

You have two ways to renew:

| Way | How |
|---|---|
| **Automatic** (default) | 24 hours before `nextDueAt`, the VPS is renewed from your credit. Turn it off or on per VPS with `PUT /services/:id/vps/auto-renew` and `{ "enabled": false }`. |
| **Manual** | Call `POST /services/:id/renew` when your customer pays you. You can renew early, but never more than one cycle ahead. |

> **Tip:** If you charge your customers by subscription, turn auto-renew **off** and call `/renew` from your app when each payment succeeds. If you prefer a "set and forget" model, leave it **on** and cancel the service when a customer stops paying you.

If an automatic renewal fails because your credit is too low, we email you and keep retrying while the VPS exists: topping up your credit is enough to bring it back.

### What happens if it is not renewed
1. **On `nextDueAt`**, the VPS is **stopped** and its IP address is released. The service becomes `suspended`. Data is kept.
2. You can still renew it during the next `deleteAfterDays` days. It comes back automatically, **possibly with a different IP address**.
3. After that, the VPS and its data are **deleted for good** and the service becomes `terminated`.

### The `billing` block
Every VPS service includes:
```json
"billing": {
  "autoRenew": true,
  "cycleDays": 30,
  "nextDueAt": "2026-11-24T10:00:00.000Z",
  "cancelRequestedAt": null,
  "priceCents": 650,
  "extraIpPriceCents": 400,
  "nextRenewal": { "amountCents": 1050, "costCents": 680, "marginCents": 370, "extraIps": 1 }
}
```
`nextRenewal.amountCents` is what your price list says to bill your customer for the next cycle; `costCents` is what it will cost you.

> **Warning:** The `billing` block and the `wholesale` fields show your costs. They are meant for your backend: do not show them to your customers.

### Cancelling
- `POST /services/:id/cancel`: the VPS keeps working until `nextDueAt`, then it is deleted. Undo it with `/resume`.
- `POST /services/:id/cancel` with `{ "immediate": true, "confirm": true }`: deleted now, with all its data.

## Suspended VPS
While a service is `suspended` (not renewed, or suspended by you from the panel) you can still read it, but every action answers `SERVICE_NOT_ACTIVE` (403). Renew it, or reactivate it from **Services → Manage**, to unlock it.

A VPS you suspend yourself from the panel is never renewed or reactivated automatically.
